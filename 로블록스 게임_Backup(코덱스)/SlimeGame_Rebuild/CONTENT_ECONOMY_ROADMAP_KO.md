# 슬라임 재료·경제·제작 로드맵

## 지금 반영한 게임 규칙

- 전체 패드는 3열 × 2행, 총 6개입니다. 기존 `Zone_1`~`Zone_3` 각각에 위·아래 패드를 둡니다. `Pad_1`만 처음부터 열려 있고, 나머지는 패드별 해금 비용(`Pad_2` 500, `Pad_3` 1,500, `Pad_4` 2,500, `Pad_5` 5,000, `Pad_6` 10,000골드)이 저장됩니다. 2·3구역 자체 해금도 기존 비용대로 별도 유지합니다.
- 패드 한 칸에는 베이스(슬라임) 하나, 토핑은 최대 3개입니다. 배치 제한은 서버에서 검사합니다.
- 노동자는 해금된 구역의 패드를 순서대로 순찰합니다. 베이스가 없는 패드도 이동 경로에는 들어가지만, 그 위에서는 골드를 벌지 않습니다.
- 베이스를 회수하면 해당 패드의 토핑과 노동자도 함께 회수하는 현재 동작을 유지합니다.

## 재료 이름과 분류

게임 용어에서는 **베이스 = 응고제가 들어가 완성된 슬라임의 기본 재료**로 통일하는 편이 명확합니다. 현실 제작에서는 풀/접착제 같은 베이스와 붕사·렌즈 세정액+베이킹소다 같은 액티베이터가 구분되지만, 게임에서 별도 제작 실패나 재료 손실을 두지 않는다면 플레이어에게 두 아이템을 따로 강제하지 않아도 됩니다. 설정 설명에서는 “응고제가 섞인 베이스”라고 설명하고, 실제 인벤토리 분류·패드 배치에서는 `Base` 한 종류로 취급하세요.

추천 베이스 초기 목록:

| 베이스 | 게임 물성 | 토핑 안정성 | 쪼물 소리/반응 |
| --- | --- | --- | --- |
| 클리어 | 투명, 기포·늘어남이 잘 보임 | 낮음 | 물기 있는 눌림, 긴 늘어남, 기포 팝 |
| 글로시/글루올 | 윤기 있고 천천히 늘어남 | 중간 | 끈적한 늘어남, 둔한 눌림 |
| 버터(클레이 혼합) | 불투명, 부드럽고 모양이 잘 잡힘 | 높음 | 포슬하고 부드러운 눌림 |
| 클레이 | 밀도와 형태 유지가 높음 | 매우 높음 | 단단하고 둔탁한 눌림, 복원 느림 |
| 휘핑/클라우드 | 가볍고 폭신함 | 낮음~중간 | 폭신한 눌림, 솜털 같은 늘어남 |
| 폼/비즈 | 알갱이가 많은 특수 베이스 | 중간 | 바스락·사각거림 |

실제 슬라임 상품/질감 분류에는 클리어, 버터, 클라우드, 플롬/비즈, 젤리, 아이스, 크런치, 글로시·두꺼운 글로시, 왁스 계열 등이 쓰입니다. 모든 명칭을 각각 별도 베이스로 출시하기보다 우선 위 6개 물성군으로 통합하고, 색/향/표면 효과와 조합해 파생 디자인을 늘리는 게 관리하기 쉽습니다. 질감 설명은 [Sloomoo의 슬라임 질감 안내](https://sloomooslime.com/pages/texture-glossary)를 참고했습니다.

`Capacity`는 쪼물 테이블의 늘어남 한계나 베이스 위 토핑 허용량을 나타내는 값으로 두고, **현재 배치 규칙은 베이스 종류와 무관하게 토핑 3개**로 고정하는 것을 권합니다. 추후 업그레이드/응고제 농도 기능이 실제로 들어갈 때만 `ToppingCapacity`를 베이스 데이터에서 사용하세요. 초기 권장값은 클리어 3, 글로시 3, 버터 4, 클레이 5, 휘핑 3, 폼/비즈 3입니다. 단, 이 값은 미래 확장안이며 현재 최대 3개 규칙을 넘기지 않습니다.

## 등급·크기·경제 규칙 초안

6개 등급은 `일반 → 고급 → 희귀 → 영웅 → 전설 → 신화` 순서입니다. 크기는 등급과 독립된 `소/중/대` 속성으로 저장합니다. 하나의 토핑 디자인을 18개 파일로 복제하지 말고, 디자인 ID + 등급 + 크기 조합을 아이템 인스턴스 정보로 관리하면 신규 디자인을 한 줄로 추가할 수 있습니다.

권장 시작 가챠 확률(등급 먼저, 그 다음 크기):

| 등급 | 전체 확률 | 소 / 중 / 대 조건부 확률 | 개별 확률: 소 / 중 / 대 |
| --- | ---: | ---: | ---: |
| 일반 | 72% | 72% / 23% / 5% | 51.84% / 16.56% / 3.60% |
| 고급 | 18% | 72% / 23% / 5% | 12.96% / 4.14% / 0.90% |
| 희귀 | 7% | 72% / 23% / 5% | 5.04% / 1.61% / 0.35% |
| 영웅 | 2.3% | 72% / 23% / 5% | 1.656% / 0.529% / 0.115% |
| 전설 | 0.6% | 72% / 23% / 5% | 0.432% / 0.138% / 0.030% |
| 신화 | 0.1% | 72% / 23% / 5% | 0.072% / 0.023% / 0.005% |

전체 확률 합계는 100%입니다. 그래서 표시 순서를 `일반 소 → 일반 중 → 일반 대 → 고급 소 …`로 정렬할 수 있습니다. 처음에는 이 수치를 무료 게임 내 코인에 사용하고, 유료 재화로 무작위 아이템을 살 수 있게 만들 경우 Roblox 규칙에 맞게 모든 결과의 숫자 확률을 구매 전에 표시해야 합니다. 확률이 높은 일반 등급 중심의 설계 참고 사례는 [Supercell Lucky Box 확률 안내](https://support.supercell.com/squad-busters/en/articles/lucky-box-drop-chances.html)입니다. 이 게임에 그대로 적용할 정답이 아니라 초안 기준으로만 사용합니다.

가격은 얻기 어려운 아이템이 끝없이 수익을 불리는 문제를 막기 위해 **획득 가격과 패드 수익을 분리**합니다.

- 상점/교환 기준 가격 배수: 등급 `1, 2, 4, 8, 16, 32`, 크기 `소 1 / 중 1.6 / 대 2.5`. 일반 소를 20골드로 잡으면 신화 대는 1,600골드입니다.
- 패드 수익(6스터드 걸음당): 베이스 0.4골드, 토핑 등급 기본값 `일반 0.25 / 고급 0.35 / 희귀 0.50 / 영웅 0.75 / 전설 1.10 / 신화 1.50`에 크기 배수 `소 1 / 중 1.25 / 대 1.5`를 곱합니다.
- 패드 토핑 3개 제한과 현재 8골드 상한 아래서 신화 대 3개를 올려도 `0.4 + 3 × 1.5 × 1.5 = 7.15골드/걸음`입니다. 기존 코드의 등급별 수익과 크게 다르므로 한 번에 기존 세이브에 덮어쓰지 말고, 실제 플레이 수치를 확인한 뒤 경제 버전/전환 규칙을 둡니다.
- 크기는 수익을 올리지만 무한 복리로 올리지 않습니다. 향료의 시간 버프, 색/광택, 토핑 시각 효과는 수익 배수와 별도 슬롯·효과로 관리하고 전체 수익 상한에 포함합니다.

## 시즌 풀의 뜻

시즌 풀은 **이벤트 기간에만 가챠/상점에 등장하는 재료 목록**입니다. 할로윈·크리스마스를 지금 억지로 넣을 필요는 없습니다. 봄에 벚꽃 시즌 풀을 켜고, 종료 후에는 획득 경로만 닫되 이미 얻은 아이템과 도감 등록은 유지하면 됩니다. 아이템 정의에 `EventTag = "SpringCherryBlossom"` 같은 태그를 붙이고 이벤트 설정에서 활성 기간·확률표를 관리합니다. 날짜가 지난 이벤트 아이템도 데이터에서 삭제하지 않습니다.

## 재료 입력 형식 목표

새 아이템은 아래처럼 한 정의만 추가하는 구조로 통일합니다. 외형/효과 에셋이 아직 없으면 기본값을 쓰고, 전용 키가 추가되면 데이터만 바꿉니다.

```lua
{
    Id = "topping_cherry_blossom",
    DisplayName = "벚꽃 폼볼",
    Category = "Topping", -- Base, Dye, Fragrance, SurfaceEffect, Topping
    Rarity = "Rare",      -- Common, Advanced, Rare, Hero, Legendary, Mythic
    Sizes = { "Small", "Medium", "Large" },
    TextureKey = "Foam",
    SoundKey = "SoftCrunch",
    VfxKey = nil,
    GoldPerStep = 0.5,
    EventTag = "SpringCherryBlossom",
}
```

새 재료 진열장은 품목별 슬롯 수가 달라질 수 있으니, 현 토핑 진열장의 10칸 저장 로직을 그대로 복제하지 말고 `Category`별 데이터 저장·렌더러를 공통화하고 각 진열장 설정에서 칸 수/배치/허용 분류를 지정합니다. 제작 순서는 **Base → Dye → Fragrance → SurfaceEffect** 진열장으로 권합니다. 쪼물 테이블은 배치 모델을 변형하지 않는 클라이언트 전용 미리보기로 시작하고, 서버는 선택한 패드의 소유권과 근접 여부만 검증합니다. 입력은 마우스/터치 드래그를 공통 포인터 흐름으로 처리하고, 사운드 키는 Roblox 오디오 에셋이 준비된 뒤 연결합니다.

## 권장 작업 순서

1. Studio에서 첫 패드만 열려 있고 나머지 패드 표지판이 보이는지, 구역 해금·패드 해금 후 패드가 실제 열리는지 확인합니다.
2. 두 번째 구역과 패드를 해금한 뒤 노동자가 실제 해금된 패드만 순환하고, 잠긴 패드와 베이스 없는 곳에서 수익이 0인지 확인합니다.
3. `ItemCatalog`를 위 재료 스키마로 확장하고 기존 ID를 유지하는 세이브 호환 변환을 추가합니다.
4. 베이스 물성·용량과 인벤토리/베이스 진열장을 먼저 연결합니다.
5. 염료, 향료, 표면 효과 진열장과 시각 효과를 연결합니다.
6. 토핑 등급·크기 생성, 가챠 확률표, 도감 정렬, 가격표를 하나의 데이터 원본으로 연결합니다.
7. 쪼물 테이블을 구현하고 입력, 눌림·늘어남 복원, 소리별 믹싱을 분리해 추가합니다.
8. 마지막으로 수익 밸런스·시즌 이벤트를 플레이 데이터에 맞춰 조정합니다.
